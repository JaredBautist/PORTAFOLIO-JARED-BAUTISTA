# Personal Portfolio Requirements

## Purpose

Create a polished personal portfolio for Jared Bautista that prioritizes demonstrable
work, communicates his full-stack and AI-assisted engineering practice, and can be
deployed to Vercel without a custom backend.

## Acceptance Criteria

1. WHEN a visitor opens the home page, the system SHALL identify Jared Bautista as a
   full-stack software engineer in Colombia and present deployed work as the primary
   proof of capability.
2. WHEN the project section is displayed, the system SHALL present live links for the
   Coworking Management Platform, MetroPizza, Menu Patios, Menu Pinar, and Jenny
   Bautista Portfolio.
3. WHEN a public project repository exists, the system SHALL provide a separate,
   clearly labelled GitHub link.
4. WHEN AXOLOT is presented, the system SHALL identify it as a published terminal AI
   coding assistant and link to its repository and npm package.
5. WHEN MIPRES work is presented, the system SHALL describe its operational purpose
   without exposing clinical data, credentials, proprietary source code, or unsupported
   production claims.
6. WHEN professional experience is displayed, the system SHALL include Jared's work at
   Clinica San Jose de Cucuta across IT support, medical-fee data analysis, MIPRES
   workflow development, and personnel entry/exit software.
7. WHEN education is displayed, the system SHALL include the Software Development
   Technologist program (2023-2025), the AI-powered Software Architecture diploma,
   Specification-Driven Development training with Amazon Kiro, and the Software
   Engineering program in progress (2026-2027).
8. WHEN the technology section is displayed, the system SHALL group verified skills by
   concern and SHALL NOT display Java, C#, Spring Boot, Firebase, AWS, Azure, MongoDB,
   or DigitalOcean.
9. WHEN the workflow section is displayed, the system SHALL explain Jared's
   specification-first process from discovery through delivery and the role of Claude
   Code, Codex, Antigravity, and Kiro.
10. WHEN a visitor selects a contact action, the system SHALL open the verified email,
    GitHub profile, or WhatsApp conversation using an actionable link.
11. WHEN the portfolio is used on a 375 px, 768 px, 1024 px, or 1440 px viewport, the
    system SHALL remain readable without horizontal scrolling or obscured controls.
12. WHEN a visitor uses keyboard navigation, the system SHALL provide semantic
    landmarks, visible focus states, descriptive accessible names, and a skip link.
13. WHEN a visitor prefers reduced motion, the system SHALL disable non-essential
    transitions and reveal animations.
14. WHEN project imagery loads, the system SHALL reserve its layout space, use locally
    optimized captures of the real deployed products, and avoid generic stock imagery.
15. WHEN the application is built for production, the system SHALL pass linting,
    TypeScript validation, and the Next.js production build without portfolio-specific
    errors.
16. WHEN search engines or social platforms inspect the page, the system SHALL expose
    descriptive metadata for Jared's role, location, and project-led portfolio.
17. WHEN a visitor selects the CV action, the system SHALL download Jared's supplied
    PDF using a readable filename without opening an untrusted external service.
18. WHEN the hero is displayed, the system SHALL show Jared's supplied portrait with
    descriptive alternative text, reserved dimensions, and responsive presentation.
19. WHEN a visitor selects English or Spanish, the system SHALL translate all visible
    portfolio copy, navigation, project descriptions, statuses, and accessible labels
    without reloading the page.
20. WHEN a language is selected, the system SHALL persist the preference locally,
    update the document language for assistive technology, and restore the selection on
    the visitor's next session; Spanish SHALL remain the initial fallback.
21. WHEN the language control is displayed on desktop or mobile, the system SHALL show
    explicit ES and EN labels, expose its selected state semantically, and remain fully
    operable by keyboard.

## Content Language

- Primary interface and professional copy: Spanish.
- Technology and product names retain their official spelling.
- English C1 proficiency is presented as a professional capability.
- Spanish is the fallback interface language; visitors can switch the complete interface
  to professional English.

## Out of Scope

- A contact form or email-delivery backend.
- A CMS, database, authentication, or admin panel.
- Publishing private clinical repositories or patient information.
- Inventing employment dates, performance metrics, certificates, or client outcomes.
- Deploying to Vercel before a destination account/project is supplied.
